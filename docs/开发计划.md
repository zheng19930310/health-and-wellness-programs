# 开发计划 · 康养项目综合管理平台（前端高保真原型）

## 1. 目标与约束

| 项 | 约定 |
| --- | --- |
| 交付物 | 单个 `index.html`（四端合一），配套需求/计划/实现说明与截图 |
| 范围 | **仅前端**，无后端、无接口；数据全部内联且为模拟数据 |
| 交互要求 | 真实增删改查（新增/编辑/删除/批量删除/检索/筛选/分页/导出/状态流转） |
| 端 | 以 Web 管理后台为主，APP 端与小程序端为高保真原型，门户首页选择端切换 |
| 视觉 | 蓝 `#1668DC` / 黑 `#0A1524` / 绿 `#00B578`；登录背景为康养实景意象 |
| 图表 | 在线 ECharts 5.5.1 |
| 账号 | 固定写死的角色账号密码，登录页提供弹框查看 |

## 2. 技术选型

- **框架**：原生 JavaScript（ES6+）+ 原生 CSS，无构建工具、无依赖打包 —— 满足「单 HTML」硬约束，同时避免 CDN 依赖失败导致整页白屏；
- **路由**：`location.hash` 手写路由（`#/login`、`#/home`、`#/admin/<模块>`、`#/screen`、`#/app`、`#/mp`），切换视图时仅重渲染目标容器；
- **状态**：单一全局状态 `S`（用户、当前视图、模块、页签、分页、关键词、筛选、选中集、移动端角色/页签）+ `MODULES` 模块注册表；
- **持久化**：`localStorage`（键 `ky_proto_v1`），首次加载写入快照 `SEED` 以支持「重置演示数据」；
- **图表**：ECharts 5.5.1（jsDelivr 主源 + `document.write` 回退 unpkg + 离线 `.noech` 占位）；
- **导出**：`Blob` + `\ufeff` BOM 生成 CSV，避免中文乱码；
- **图像**：登录背景由生成图压缩为 1600×915 JPEG（约 268 KB）后转 base64 内联，保证单文件且离线可用；
- **测试**：Playwright + Chromium 无头脚本做冒烟与截图（登录 → 门户 → 29 模块遍历 → CRUD → 流程 → 大屏 → 四端交互）。

## 3. 架构分层

```
index.html
├─ Layer 0  设计令牌与全量 CSS（四端共用，BEM 风格类名）
├─ Layer 1  数据层  ACCOUNTS / ROLE_MENUS / MODULES（schema + 内联模拟数据）
├─ Layer 2  内核层  状态 S / 持久化 / 路由 / RBAC / 弹框 / Toast / 日志
├─ Layer 3  引擎层  Schema 驱动表格 + 表单 + CRUD + 状态机 FLOWS + CSV 导出
├─ Layer 4  可视化  驾驶舱三视图 / 数字孪生 / 报表 / 实时监测 / 大数据屏
└─ Layer 5  移动端  APP 与小程序原型（MB 渲染器 + Mob 动作集）
```

核心思想是**用一份 schema 描述换 40+ 个界面**：模块只需声明 `cols`（字段类型、下拉项、标签色、是否入表/入表单/可筛选）与 `rows`，即可获得检索、筛选、分页、增删改查、详情、批量操作、导出与流程按钮；差异化的驾驶舱、孪生、报表、实时监测与移动端以 `custom` / 独立渲染器实现。

## 5. 模块开发顺序（后台）

园区总览（驾驶舱 → 孪生 → 报表）→ 长者服务（档案 → 健康 → 请假 → 关怀 → 子女 → 投诉）→ 服务运营（活动 → 预约 → 计划 → 提醒 → 清洁 → 康养圈）→ 健康促进（运动 → 膳食四页签 → 心理 → 临终 → 课堂 → AI → 防诈）→ 消费经营（会员/套餐/订单/积分）→ 设备安防（设备五页签 → 录像三页签 → 生物识别三页签 → OCR）→ 系统（组织/角色/账号/日志/参数）→ 外部对接（接口/授权映射/调用日志）。

先做总览与高频业务模块，保证可演示价值最高；页签型模块（膳食、消费、设备、录像、生物识别、系统、对接）复用同一引擎，边际成本低。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 单文件体积过大导致编辑困难 | 分层文件（p1–p6）开发 + 构建脚本拼接，交付时合并为单文件 |
| ECharts CDN 不可达 | 双源回退 + 图表区占位提示，其余功能不受影响 |
| 模块数量多、界面重复 | Schema 驱动引擎，新增模块仅写数据定义 |
| 演示数据被误改后不可恢复 | 启动时快照 `SEED`，提供「重置演示数据」 |
| 大屏在低分辨率下溢出 | 网格 + `minmax` + 弹性面板，按 1920×1080 校准并允许滚动 |
| 移动端「原型」易流于静态 | 所有关键动作写入共享数据模型，形成跨端闭环可验证 |
| 敏感信息误用 | 全部虚构姓名/证件/手机号脱敏格式，文档中明确声明 |
