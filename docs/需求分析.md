# 需求分析 · 康养项目综合管理平台

> 输入：《康养项目综合管理平台 PRD》（V1.1，约 1375 行）。本文将 PRD 拆解为可开发的需求清单，并明确本期（前端高保真原型）的实现范围与验收口径。

## 1. 项目背景与目标

园区由**旅游区 / 康养区 / 文化区**三大分区组成，提供旅居、康养、文化社交、健康管理与生活照料的一体化服务。原有管理方式存在四类问题：长者信息分散、健康风险发现滞后、服务过程无法留痕、子女与家人缺少参与入口。

平台目标可归纳为四句话：

- **对长者**：安全有保障、健康有监测、生活有服务、精神有陪伴；
- **对子女**：远程可见、可托付、可代付、可参与；
- **对运营**：服务全流程线上闭环、设备与告警统一处置、经营数据可决策；
- **对管理**：多角色分权、数据可审计、对外可对接。

产品形态为「**四端 + 一中心**」：Web 管理后台、APP 端、小程序端、数字中心大屏，统一门户与统一账号权限体系。

| 2 | 管理决策层 | 经营与服务质量总览、督办、报表订阅 | Web / 大屏 |

| 5 | IoT 设备管理员 | 设备台账、告警处置、联动规则、录像与生物识别 | Web / 大屏 |
| 6 | 投诉与服务监督 | 工单受理、升级督办、满意度回访 | Web |
| 7 | 社工 / 志愿者 | 人文关怀、活动与课堂执行、康养圈运营 | Web / 小程序 |

## 3. 功能需求清单（Web 管理后台）

按 PRD 功能域拆解，标注本期实现方式（CRUD = 通用增删改查引擎；FLOW = 带状态流转；CUSTOM = 定制视图）。

### 3.1 园区总览
| 模块 | 关键需求 | 实现 |
| --- | --- | --- |
| 数字中心驾驶舱 | 经营服务看板、数字孪生、3D 导航监控三视图切换；KPI 聚合；一键投放大屏 | CUSTOM |
| 数字孪生 / 3D 监控 | 三维园区底图叠加设备/告警/人员/能耗图层，点选设备看实时读数与视频联动，导航路线下发 | CUSTOM |
| 统计报表 | 收入/入住/转化/满意度趋势，服务量构成，长者结构与照护等级，维度切换与明细导出 | CUSTOM + CRUD |

### 3.2 长者服务
个人档案管理（全生命周期建档、套餐签约、标签、状态）、健康与病例档案（手环体征、护理/理疗记录、体检、病例、子女授权）、请假管理（申请→审批→外出→销假/逾期告警，FLOW）、人文关怀（生日/节日/纪念日/住院慰问/情绪疏导，含执行结果与满意度）、子女服务管理（亲属绑定审核、授权范围、通知偏好、代付额度、探望记录）、投诉与建议（多渠道受理、SLA 时限、升级督办、回访闭环）。

### 3.3 服务运营
组织活动管理（发布、报名与候补、场地排期、扫码/人脸签到、满意度复盘）、预约体验管理（项目配置、预约单、资源冲突校验、到访核销、转化线索）、院内计划管理（年度/月度计划、审批、进度推进）、事项提醒中心（用药/复诊/缴费/探视，多通道触达与回执）、康养圈与在院时光（动态发布、内容审核、时光轴、子女留言、同步开关）、卫生清洁管理（排期、执行登记、检查验收与整改）。

### 3.4 健康促进
运动与健身（运动处方、时长/步数/心率/消耗、达标状态、异常中止）、膳食与营养（菜单库、饮食档案与忌口、配餐计划与营养评估、供餐执行与留样，四页签）、心理管理（测评、干预、转介）、临终关怀（阶段、症状控制、人文与家属支持）、老年课堂（课程、报名、签到、作品展示）、AI 聊天陪伴（会话记录、情绪识别、预警派单、人设配置）、防诈守护（风险通话/链接识别、拦截结果、关怀安排）。

### 3.5 消费经营
消费与会员（会员分级与成长值、套餐产品、订单与核销、储值与积分，四页签）。要求支持子女代付、联合支付、积分抵扣、发票状态。

### 3.6 设备安防
物联网设备管理（设备台账、实时监测、设备告警、联动规则、固件与运维工单，五页签）；监控录像管理（摄像头点位、录像任务、回放与导出授权）；生物识别管理（特征库、门禁绑定、识别记录、授权撤回）；OCR 识别（证件/单据识别、置信度、校对入库）。

### 3.7 系统
系统管理（组织、角色权限、账号、操作日志、参数配置，五页签）；外部平台对接（接口管理、授权与字段映射、调用日志，三页签）。要求「先授权、后传输、最小化、可审计」。

## 4. 数据与字典要点

- **分区/区域**：康养区 A/B/C 栋、文化区、旅游区旅居客房、公共走廊、营养餐厅；
- **设备类型**：智能手环、运动手环、摄像头、门禁、温湿度传感器、加湿器、空调/新风、照明、床垫监测、紧急呼叫按钮、烟感报警、人脸识别终端、智能体测设备、智能插座；
- **照护等级**：自理 / 半自理 / 失能 / 专护；**健康风险**：低 / 中 / 高；
- **会员等级**：基础 / 银卡 / 金卡 / 钻石（对应权益与折扣）；
- **告警分级**：I 级（紧急，3 分钟响应）/ II 级（重要）/ III 级（提示），并定义联动动作（抓拍、开门、通知值班与子女）；
- **状态机**：审批（待审批→已同意→外出中→已销假/逾期）、受理（待受理→处理中→待回访→已闭环/已升级督办）、核销（待支付→已支付→已核销/已退款）、处置（待处置→处置中→已闭环/误报）、推送（待推送→已推送→已确认/未确认）、审核（待审核→已发布/已隐藏）、拦截（关注中→成功拦截→已报案）。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 适老化 | 大字号、高对比、语音入口、SOS 一键可达、减少层级；关键操作二次确认 |
| 安全合规 | 敏感数据（身份证、健康、生物特征、录像）脱敏展示、授权可见、操作留痕、可撤回 |
| 性能 | 单页路由切换 < 200ms；表格分页 8 条/页；大屏图表 5s 刷新不抖动 |
| 一致性 | 四端共享同一份数据与状态，任一端操作即时反映到其他端与角标 |
| 可运维 | 参数化配置（告警阈值、SLA、订阅开关）、日志可检索导出 |
| 兼容 | Chrome / Edge 现代浏览器；1440×900 起，大屏按 1920×1080 设计 |

## 6. 本期范围与验收口径

**做**：四端全部界面与交互（前端单文件）、真实增删改查与状态流转、模拟数据内联、ECharts 大屏、角色与端权限、演示账号弹框、CSV 导出、localStorage 持久化与重置。

**不做**（PRD 中依赖服务端或第三方能力的部分，以界面与流程模拟表达）：真实登录鉴权与短信、数据库与接口、设备直连与协议解析、AI 模型推理、人脸识别/OCR 真实算法、三维引擎、支付与发票、消息推送通道。

**验收**：① 任一角色可登录并只看到授权模块；② 任一模块可完成新增/编辑/删除/批量删除/检索/筛选/分页/导出；③ 关键流程可推进状态且产生跨模块记录（如逾期→告警）；④ 大屏图表正常渲染并自动刷新；⑤ APP/小程序原型可切换角色并完成报名、订餐、请假、发布、点赞、代付、SOS 等动作，且后台数据同步变化。
