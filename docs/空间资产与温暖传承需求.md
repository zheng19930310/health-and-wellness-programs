# 空间资产 · 温暖传承 · 需求记录与分析

## 一、用户原话（需求来源）

> 增加新的原型内容：
> web 端：
> 1. 不同区域的楼宇、房间、iot 设备；
> 2. 住客房间入驻的绑定、退租；
> web 端和移动端：
> 拓展温暖与传承方面的产品能力，即相册和日记；
> 1. 可以创建自己的相册，有添加和销毁，相册还可以打印成纸质的，也可以进行分享，有不同的相册分类；
> 2. 日记可以笔记、录音、画画、拍照，都可以记录；
> 3. 日记、照片可以联动做成传承，辅助生成 AI 个人传记，然后人可以自由编写；
> 记录需求、分析需求，并实现和推送 git。

## 二、需求分析

### 2.1 空间资产（Web 端）

| # | 需求 | 拆解 | 原型落点 |
|---|---|---|---|
| 1 | 不同区域的楼宇 | 园区 → 分区（康养区/文化区/旅游区/生活配套区）→ 楼栋，楼栋要有业态、层数、房间数、床位、在住、管家、消防等级、启用状态 | 新增菜单组「空间资产」→ `building` 区域与楼栋台账（CRUD + 报修停用/恢复启用流程） |
| 1 | 房间 | 楼栋下的房间：房号、楼层、房型、床位、面积、朝向、适老化改造、月租、状态（空置/已入住/维修中/预留/清洁中）、当前住客 | `room` 房间台账（CRUD + 分配/维修/释放流程） |
| 1 | IoT 设备 | 设备已散落在「设备台账」，需要按 **区域→楼栋→房间** 逐级下钻看到房间内的设备与实时读数，并支持为房间新增/解绑设备 | `space` 空间资产总览（自定义四栏联动视图，复用 `MODULES.device`，按房号匹配 `no/name/pos/bind`） |
| 2 | 住客房间入驻的绑定 | 签约 → 绑定房间（房间转「已入住」、档案写入区域房号、手环等设备绑定住客）| `stay` 入住绑定与退租 + `stay` 流程「绑定房间」，跨模块联动 |
| 2 | 退租 | 申请退租 → 退租结算（房间转「空置」、清空住客、档案转「离园」、解绑设备） | `stay` 流程「申请退租 / 退租结算」；另支持「换房」并同步房间归属 |

> 关键设计：绑定/退租/换房不是"改一个状态字段"，而要真实驱动 `room`、`archive`、`device` 三张表联动，才讲得通"入住办理"这条业务主线。为此在通用流程引擎 `Crud._flow` 上增加 `after(row)` 钩子。

### 2.2 温暖与传承（Web 端 + 移动端）

| # | 需求 | 拆解 | 原型落点 |
|---|---|---|---|
| 1 | 创建自己的相册 | 新建相册（名称/分类/封面/权限）、添加照片、**销毁**相册（确认+留痕）、删除单张 | `album` 温暖相册（卡片墙 + 照片墙 + 弹层操作），长者端 APP/小程序同源可建可加 |
| 1 | 相册分类 | 人生历程 / 家庭团聚 / 节日庆典 / 旅居风景 / 活动剪影 / 手迹作品 | 分类 chips 过滤 + 分类徽标 |
| 1 | 打印成纸质 | 选纸张（6 寸 / A4 / 相册书）、份数、装订，输出可打印版式并调用浏览器打印 | `printSheets()` 打印层（`@media print` 仅输出打印区）+ 打印次数累计 |
| 1 | 分享 | 分享范围（仅自己/家人/园区公开）、有效期、生成链接与分享码 | 分享弹层（链接 + 假二维码 + 权限），回写 `share/shareExp` |
| 2 | 日记四种记录方式 | 笔记（文字）、录音（计时 + 语音转文字）、画画（Canvas 手写板）、拍照（取景 + 说明） | `diary` 时光日记：四类记录混排时间线 + 四页签创作面板，画画用真实 Canvas 生成缩略图 |
| 3 | 联动做成传承 | 勾选某位长者的日记 + 相册照片作为素材 → 生成 AI 个人传记（分章节、引用真实素材）→ 人工自由编写 → 定稿交付子女 | `legacy` 传承 · AI 传记：素材勾选 → 生成进度 → 章节可编辑 → 定稿/交付/打印 |

> 关键设计：相册、日记、传记三份数据互为输入（传记的正文由真实日记与照片标题拼装），Web 与移动端共用一个 `Warm` 能力层，避免两套逻辑漂移。

### 2.3 权限与可见范围（RBAC 增量）

- 超级管理员：全部可见；`iot / guard / clean`：空间资产（楼栋、房间、空间视图）；`manager / ops`：含入住绑定与退租；
- `ops / doctor / social / manager`：温暖传承三模块（照护与人文关怀视角）；`elder / child / special`：温暖传承（本人视角，主要在手机端使用）。

## 三、实现要点

### Web 后台
1. **空间资产总览**（`CUSTOM.space`）：左「分区/楼栋」树 → 中「楼层房间网格」（状态色块 + 房号 + 住客 + 设备数）→ 右「选中房间详情」：环控读数、设备清单、入住合同、快捷动作（新增设备 / 去入住办理 / 标记维修）。顶部 KPI：总房间、在住、空置、维修、设备总数、在线率。
2. **区域与楼栋 / 房间台账 / 入住绑定与退租**：沿用 schema 驱动 CRUD（检索、筛选、分页、批量删除、CSV 导出、详情关联），新增 `building / room / stay` 三组流程动作。
3. **温暖相册**（`CUSTOM.album`）：分类 chips + 相册卡片（封面、归属长者、照片数、权限、分享/打印次数）→ 打开照片墙；新建 / 添加照片 / 单张删除 / 销毁 / 分享 / 打印。
4. **时光日记**（`CUSTOM.diary`）：左侧长者与类型筛选 + 时间线（四类图标），右侧创作面板四页签（笔记 / 录音 / 画画 / 拍照），列表支持朗读、重听、放大画作、删除。
5. **传承 · AI 传记**（`CUSTOM.legacy`）：选长者 → 素材勾选（日记 / 相册，含字数与照片数统计）→ 传记风格（温情回忆录 / 家书体 / 编年史 / 口述实录）→ 生成分章草稿（带进度动画）→ 逐章自由编写保存 → 定稿 / 交付子女 / 打印成书。

### APP 端 / 小程序端
- 长者端新增底部 Tab「📖 温暖」：我的相册（卡片 → 照片墙 → 分享/打印）、我的日记（时间线 → 写日记：笔记/录音/画画/拍照）、我的传记（阅读 / 口述续写）。
- 子女端新增底部 Tab「📖 传承」：父母的相册与日记（授权可见）、AI 传记阅读、帮长辈补写一章、送祝福。
- 所有弹层走手机屏内 `.sheet` 底部弹层（与紧急监管端、长者端订餐一致的样式约束），不逃逸到视口。
- 移动端新增的相册/日记会即时出现在 Web 端列表（同一份 `MODULES` + `persist()`）。

### 数据与联动
- 新增模块：`space`（自定义）、`building`、`room`、`stay`、`album`（自定义）、`diary`（自定义）、`legacy`（自定义）；新增菜单组 `空间资产`、`温暖传承`。
- 联动点：绑定入住 → 房间「已入住」+ 住客 + 档案区域房号 + 设备 `bind`；退租结算 → 房间「空置」+ 住客清空 + 档案「离园」+ 设备解绑；换房 → 新旧房间归属互调；相册/日记 → 传记素材；传记交付 → 生成子女端提醒与操作日志。

## 四、验收口径

1. Web 侧栏出现「空间资产」「温暖传承」两组菜单，非授权角色不可见；
2. 空间视图点区域→楼栋→房间三级下钻，右栏能看到该房间真实绑定的 IoT 设备与读数；
3. 合同「绑定房间」后，房间台账该房变「已入住」且住客正确；「退租结算」后房间变「空置」，档案转「离园」；
4. 相册可新建/加片/销毁/分享/打印，打印会唤起浏览器打印且只有相册版式进入纸张；
5. 日记四类都能落库并在时间线正确显示类型图标，画画保存后能看到自己的笔迹；
6. 传记生成引用了勾选的日记与照片，章节可编辑并保存，交付后子女端可见；
7. 手机端温暖/传承 Tab 全部弹层位于手机屏内，刷新后与 Web 数据一致。
