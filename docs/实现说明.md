# 实现说明 · 康养项目综合管理平台（单 HTML 前端原型）

本文记录 `index.html` 的实现方式、数据结构、关键交互与演示脚本，便于后续接手或二次开发。

## 1. 文件构成

交付物只有一个 `index.html`（约 670 KB），内部按六个层次顺序拼接（源码分层保留在 `p1_head.html / p2_body.html / p3_data.js / p4_core.js / p5_charts.js / p6_mobile.js`，用构建脚本合并并把登录背景 base64 注入 `__LOGIN_BG__` 占位符）：

| 层 | 内容 | 规模 |
| --- | --- | --- |
| L0 | `<head>`、设计令牌、四端全量 CSS | ~500 行 |
| L0' | 视图骨架：`#v-login / #v-home / #v-admin / #v-screen / #v-app / #v-mp` + 通用弹层 `#mask/#modal` | ~185 行 |
| L1 | 账号、角色菜单、模块 schema 与内联数据 | ~1315 行，56 模块 / 44 数据集 / 约 450 条记录 / 488 字段 |
| L2 | 状态、持久化、路由、RBAC、弹框、Toast、日志、门户、侧栏、消息中心 | — |
| L3 | 表格与表单引擎、CRUD、批量、分页、检索筛选、CSV、详情、关联、状态机 | — |
| L4 | 驾驶舱三视图、数字孪生、报表、设备实时监测、大数据屏（ECharts） | — |
| L5 | APP / 小程序原型渲染器与动作集、3D 导航下发、启动引导 | — |

## 2. 数据结构

### 2.1 账号与权限

```js
const ACCOUNTS = [{ u:'admin', p:'admin123', name:'郑克俊', role:'超级管理员', roleKey:'admin',
                    ends:['home','admin','screen','app','mp'], desc:'…' }, …];   // 10 个固定账号
const ROLE_MENUS = { admin:'*', manager:[…], ops:[…], doctor:[…], iot:[…],
                     service:[…], social:[…], clean:[…], elder:['dashboard','archive'], child:[…] };
```

`ends` 决定登录时可选的端（越权时提示并回落到门户），`ROLE_MENUS` 决定侧栏可见模块与 `canAccess()`。

### 2.2 模块注册表（schema 驱动）

```js
M('leave', {
  title:'请假管理', icon:'📝', grp:'长者服务', flow:'leave',        // flow → FLOWS 状态机
  desc:'外出/离园申请、规则审批、销假确认、逾期自动告警…',
  cols:[
    { k:'name',  t:'申请人', type:'select', opts:ELDER_NAMES, req:1, filter:1 },
    { k:'start', t:'开始时间', type:'datetime', req:1 },
    { k:'status',t:'状态', type:'select', opts:[…],
      tag:{'待审批':'warn','外出中':'purple','逾期':'red',…}, filter:1, noform:1 },
    …
  ],
  rows: R(['name','type','start',…], [['徐世昌','回家探亲','2026-10-27 09:00',…], …])
});
// 页签容器：M('meal', { tabs:['menu','diet','配餐计划|arrange','供餐执行|serve'] })
// 定制视图：M('dashboard', { custom:'dashboard' })
```

字段属性：`type`（text/textarea/num/money/date/datetime/select/avatar）、`opts`/`dyn` 下拉项、`tag` 状态色映射、`req` 必填、`notbl` 不入表、`noform` 不入表单、`filter` 生成筛选器、`mono` 等宽、`placeholder`、`unit`。
由此自动获得：列表渲染、状态标签着色、关键词检索、多条件筛选、分页（默认 8 条）、新增/编辑表单与校验、删除与批量删除、CSV 导出、详情页与跨模块关联记录。

### 2.3 状态与持久化

```js
const S = { user, view, mod, tab:{}, page:{}, kw:{}, flt:{}, sel:{}, mobileRole:{app:'elder',mp:'elder'}, appTab, mpTab, folded };
snapshot();  // 首次把每个模块 rows 深拷贝到 SEED，供「重置演示数据」
persist();   // 每次写操作后：localStorage['ky_proto_v1'] = { u, d:{模块:rows} }
restore();   // 启动时回填，并把 UID 推到最大值
```

## 3. 路由与四端切换

`App.go(view, mod)` 仅修改 `location.hash`，`route()` 解析后隐藏所有 `.view`、给目标视图加 `.on`，并按视图调用 `renderHome / renderNav+renderPage / initScreen / renderMobile`。
门户首页 `#v-home` 展示当前角色的 KPI、四个「端入口」卡片、核心业务闭环示意、角色权限矩阵与今日待办，即需求中的「通过首页选择不同端来切换展示」；后台顶栏「🖥 切换端」下拉可在四端之间随时跳转。

## 4. CRUD 与流程引擎

- `Crud.open(key,id)` 生成表单（`fieldHTML`），`Crud.save` 做必填校验、`autoFill` 自动补齐编号/时间/默认状态，写回 `rows` 并 `persist()` + 重渲染 + `logAct()`；
- `Crud.del / batchDel` 走二次确认弹框；`Crud.detail` 输出字段明细 + `related()` 跨模块关联（按姓名/设备号等匹配）；`archive` 使用 `detailArchive` 汇聚档案、体征、请假、消费、关怀；
- `FLOWS` 定义 20+ 状态机动作，元素形如 `{t:'同意', st:'待审批', to:'已同意', set:r=>({approver:…}), ask:'审批意见', note:'result', push:'…'}`：`ask` 触发填写弹框（写入留痕字段），`to` 可为函数（如按计划进度推进），`push` 调用 `pushAlert()` 生成设备告警并联动大屏、消息中心与子女端；
- `badgeCount(key)` 为每个模块定义「待处理」判定，驱动侧栏角标与门户待办；`logAct()` 写入系统操作日志（含端、风险级别）。

## 5. 可视化实现

- **驾驶舱**（`CUSTOM.dashboard`）：8 个 KPI + 视图切换（经营看板 / 数字孪生 / 3D 导航监控），经营看板为 12 个月收入-入住率-活动双轴图、服务量构成、告警中心与今日待办；
- **数字孪生**（`CUSTOM.twin`）：SVG 园区底图 + 分区面板 + 设备定位点（按类别着色，告警点闪烁），点击设备弹出实时读数与视频联动模拟；图层开关、视频墙、导航路线 `navRoute()` 五步下发；
- **报表中心**（`CUSTOM.reports`）：收入/入住/转化趋势、服务量构成、长者结构与照护等级、维度切换、明细导出；
- **实时监测**（`CUSTOM.monitor`）：设备列表 + 每 3 秒抖动的模拟读数（心率、血氧、温湿度、电量）与阈值提示；
- **大数据屏**（`initScreen`）：1920×1080 三栏深色布局，6 个 ECharts（饼图、柱图、条形 TOP5、雷达在线率、30 日双轴趋势、旭日告警类型）+ KPI 带 + 孪生映射 + 实时告警流 + 热度榜 + 跑马灯；`setInterval` 5 秒刷新图表、9 秒随机生成新告警，切出视图即清理定时器。
- `ec(id,opt,dark)` 统一封装：无 ECharts 时输出 `.noech` 占位；`CHARTS` 缓存实例并在窗口 `resize` 时 `resize()`。

## 6. 移动端原型（APP / 小程序）

`MB` 为渲染器，`Mob` 为动作集，`MB_TABS[kind][role]` 描述底部 Tab 结构；`renderMobile(kind)` 依据 `S.mobileRole[kind]` 与 `S[kind+'Tab']` 输出「状态栏/胶囊栏 + 头部 + 内容 + 底部 Tab」，左侧 `#appRole / #mpRole` 分段控件切换长者端与子女端。

长者端页面：首页（会员卡、体征三卡、8 宫格快捷、今日提醒、活动报名、亲情视频）、健康（7 日体征 ECharts 折线、档案摘要、运动处方、体征记录、在线问诊）、服务（订餐购物车、扫码/人脸核销、我的预约）、康养圈（分类筛选、点赞、发布、留言）、我的（会员卡、家人、适老化开关）。
子女端页面：首页（父亲状态、待办与告警、8 宫格）、亲情（授权说明、体征、AI 会话摘要、留言、录像申请）、预约（探望/代约表单 + 记录 + 代请假）、消费（待支付代付、充值、消费明细）、我的（授权与代付、家庭成员）。

关键动作全部落到共享数据：`Mob.signup / mealSubmit / bookSubmit / leaveSubmit / postSend / commentSend / like / sport / remind / scan / repairSend / pay / topay / aiAsk+aiClose / sos+sosGo / video`。其中 AI 陪伴在识别到「情绪低落」时会 `pushAlert` 并自动生成「情绪疏导」关怀任务；SOS 3 秒倒计时后生成 I 级告警，可在后台「设备与告警中心」和大屏告警流中看到。

## 7. 视觉与适老化

CSS 变量统一蓝/黑/绿主色与深浅梯度；后台为浅色内容区 + 深色侧栏，大屏与孪生为深色主题（带角标面板、辉光描边）；移动端使用 392×812 手机壳（含刘海、状态栏、小程序胶囊栏）。长者端默认大字号高对比、主色按钮、单层可达 SOS，符合适老化要求。

## 8. 演示脚本（建议 6 分钟）

1. `admin / admin123` 登录（登录页先点「👁 查看演示账号密码」展示弹框）→ 门户首页；
2. 进入 Web 后台：驾驶舱三视图切换 → 请假管理「同意/销假/逾期告警」→ 设备与告警中心查看联动告警 → 个人档案新增一位长者并查看详情/导出 CSV；
3. 打开数字大屏：图表刷新、点击孪生设备点、观察告警流与跑马灯；
4. 切到 APP 端长者：活动报名 → 今日订餐加购提交 → 康养圈发布动态 → AI 陪伴说「我有点想家」→ SOS 呼救；
5. 切到 APP 端子女：查看告警与体征 → 探望预约 → 为待支付订单代付 → 充值 1000；
6. 回到 Web 后台：观察活动已报名 +1、订单已支付、康养圈待审核 +1、请假待审批 +1、告警新增、操作日志留痕；
7. 用 `clean / 123456` 或 `elder / 123456` 登录，展示不同角色的端与模块差异；最后「重置演示数据」还原。

## 9. 已知限制

- 无服务端：不存在并发、事务与真实鉴权；数据仅存于本机浏览器；
- 手机号/身份证为脱敏格式的虚构值，`138****2231` 等不可回拨；
- 三维、人脸识别、OCR、AI 语义、支付与消息通道均为界面与流程模拟；
- 大屏按 1920×1080 校准，更小分辨率会出现缩放留白；
- 打印样式与国际化未纳入本期。
